## Basic Usage

`VfKnob` wraps PrimeVue's [Knob](https://v4.primevue.org/knob/) and forwards its entire API — original props, events, and slots all work as documented, apart from the few exceptions in the [PrimeVue Props](#props.props-primevue) table. On top of that, Vueform adds its own props, events, slots, and features — data binding, validation, conditions, and layout — which the examples on this page demonstrate.

::: usage center

```vue [Preview]
<VfKnob name="volume" :min="0" :max="100" :step="5" />
```

```vue [Template]
<VfKnob
  name="volume"
  label="Volume"
  :min="0"
  :max="100"
  :step="5"
  :default-value="40"
  centered
/>
```

```vue [Schema]
<script setup lang="ts">
import { defineSchema, useForm } from '@vueform/primevue'

const schema = defineSchema({
  volume: {
    type: 'knob',
    label: 'Volume',
    min: 0,
    max: 100,
    step: 5,
    defaultValue: 40,
    centered: true,
  },
})

const [Form] = useForm({ schema })
</script>

<template>
  <Form />
</template>
```

:::

For the official PrimeVue examples, visit [Knob](https://v4.primevue.org/knob/).

## Dynamic Props

The `min`, `max`, and `step` props accept expression strings, allowing their values to be derived from other form fields dynamically.

::: usage

```vue [Preview]
<VfKnob name="volume" min="{min}" max="{max}" step="{step}" />
```

```vue [Template]
<VfKnob
  name="volume"
  label="Volume"
  min="{min}"
  max="{max}"
  step="{step}"
  :default-value="50"
  :space-bottom="1"
  line-bottom
  centered
/>
<VfInputNumber
  name="min"
  label="Min"
  :default-value="0"
  :columns="4"
  icon-after="cog"
/>
<VfInputNumber
  name="max"
  label="Max"
  :default-value="100"
  :columns="4"
  icon-after="cog"
/>
<VfInputNumber
  name="step"
  label="Step"
  :default-value="5"
  :columns="4"
  icon-after="cog"
/>
```

```vue [Schema]
<script setup lang="ts">
import { defineSchema, useForm } from '@vueform/primevue'

const schema = defineSchema({
  volume: {
    type: 'knob',
    label: 'Volume',
    min: '{min}',
    max: '{max}',
    step: '{step}',
    defaultValue: 50,
    centered: true,
    lineBottom: true,
    spaceBottom: 1,
  },
  min: {
    type: 'input-number',
    label: 'Min',
    defaultValue: 0,
    columns: 4,
    iconAfter: 'cog',
  },
  max: {
    type: 'input-number',
    label: 'Max',
    defaultValue: 100,
    columns: 4,
    iconAfter: 'cog',
  },
  step: {
    type: 'input-number',
    label: 'Step',
    defaultValue: 5,
    columns: 4,
    iconAfter: 'cog',
  },
})

const [Form] = useForm({ schema })
</script>

<template>
  <Form />
</template>
```

:::

## With Slider

The `default` prop accepts an expression string, allowing the knob's value to be driven by another field.

::: usage center

```vue [Preview]
<VfKnob name="knob" default-value="{value}" readonly />
<VfSlider name="value" :default-value="50" />
```

```vue [Template]
<VfKnob name="knob" label="Knob" default-value="{value}" readonly centered />
<VfSlider name="value" :default-value="50" />
```

```vue [Schema]
<script setup lang="ts">
import { defineSchema, useForm } from '@vueform/primevue'

const schema = defineSchema({
  knob: {
    type: 'knob',
    label: 'Knob',
    defaultValue: '{value}',
    readonly: true,
    centered: true,
  },
  value: {
    type: 'slider',
    defaultValue: 50,
  },
})

const [Form] = useForm({ schema })
</script>

<template>
  <Form />
</template>
```

The `info` prop displays an info icon next to the label that shows a tooltip on hover. The element must have a `label` for the info icon to appear. The `infoPosition` prop controls the tooltip placement.

```vue [Preview]
  name="speed"
  info="Controls the animation playback speed as a percentage."
/>
```

| [`handleInput()`](!code#context.handleInput "(payload: any, e: Event \| undefined) => void") | Handles a user-initiated change end to end. Bind it to the one event that means "the user changed it": `@input` for native text inputs, `@change` for native checkbox / radio / select / file controls, `@update:model-value` for components — alongside `v-model`, or without it.<br><br>Accepts the new value or the native event carrying it (an event's value is read the way `v-model` reads it); a plain value may pass the originating event as the second argument so composition filtering still applies. Events fired during an IME composition session are ignored — the composed text arrives once, when the session ends.<br><br>The value is written to the model only when the model doesn't hold it yet — with `v-model` in place this is a pure user-input notification, without it `handleInput` performs the write itself. Values resolved from native events are only picked up while `canonicalDomValue` is on; on formatted inputs (masks) the event carries display text, so only the notification fires, with the current model value as the payload. Either way it reports the input: fires the `input` event with `(value, event, context$)` and triggers `validateOn` / expression untracking. It does **not** touch the interaction states — `visited` and `touched` come from `handleFocus` / `handleBlur`. |
